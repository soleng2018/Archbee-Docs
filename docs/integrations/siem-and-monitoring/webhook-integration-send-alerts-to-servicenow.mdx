### Create ServiceNow New Field for Nile Service

- The next step is to create a Java scripted Rest APIs which handles the Webhooks requests from Nile notification-services. Below is the Java script that we will use to create the API:



<BlockQuote>
  (function process( /\*RESTAPIRequest\*/ request, /\*RESTAPIResponse\*/ response) \{
  request.body.data;
  var alert = request.body.data;
  var state = 2;
  if (alert.alertStatus == 'Resolved') \{
  state = 6;
  }
  var inc = new GlideRecord('incident');
  inc.addQuery('u\_external\_id', '=', alert.id);
  inc.query();

  if (inc.next()) \{
  inc.state = state;
  if (state == 6) \{
  inc.close\_code = 'Closed/Resolved By Caller';
  inc.close\_notes = 'Closed by API';
  }
  inc.update();
  } else \{
  inc.initialize();
  inc.u\_external\_id = alert.id;
  inc.short\_description = alert.alertSubject;
  inc.description = alert.alertSummary + " for " + alert.duration;
  inc.insert();
  }
  response.setStatus(200);
  })(request, response);

</BlockQuote>

Note: you can customize the script.
&#x20;For more information on ServiceNow API scripts use the following URL:

**https\:// + \<instance name> + \<resource path>**

In our example, it will be https\://dev119912.service-now\.com/api/832604/nile\_alert. You will need the URL for API postman verification and Nile integration.

Open **Postman** application.
Select **POST**,and provide the API URL.
Click on **Authorization&#x20;**, select **Type Basic Auth, &#x20;**&#x61;ndprovide ServiceNow instance admin credentials (user/password admin/=EZ\*g23IjdTi)

### Webhook :Comment[Enhancements]{docCommentId="i403s1WCXbOEc7StCf3xC" resolved="false"}:

The Nile Portal now includes the following webhook enhancements.

- **Custom hostname for Nile Elements (NE)**
  You can now configure a custom hostname for Nile Elements. The configured hostname is reflected in webhook notifications, enabling better alignment with your internal naming conventions and downstream systems. In addition, the **Download** function on the **Nile Device Inventory** page now includes the operator/admin-modified hostname alongside other device parameters and also retains the original default device name for cross-reference.



- **Closet added to location hierarchy**
  The **Closet** level is now included in the location hierarchy and is visible in the **Location** column on the **Inventory&#x20;**&#x70;age. This :Comment[provides]{docCommentId="behpdC5aqYvGI-It_QDWR" resolved="false"} more granular physical context for device placement.

![](https://api.archbee.com/api/optimize/6swSwg1BT-BlfEPtYJhxM/tZ1qw8yLpGxhE8_zlF9AW_.blob "Figure 1: Example view showing custom hostname for a Nile Element and Closet in the location hierarchy on the Inventory page.")

- **Additional webhook payload attributes as separate fields**
  The webhook notification JSON body now exposes several attributes as dedicated fields, simplifying parsing and integration. Newly available fields include:
  - Custom NE name
  - device\_type
  - Serial Number (**SN**)
  - severity
  - deviceId (a Nile-generated unique identifier for continued reference and correlation)
