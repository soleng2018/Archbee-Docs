Introduction

This document provides a validated step-by-step configuration of a wireless Dot1x SSID on the Nile Service Block (NSB) with Aruba ClearPass.
&#x20;The configuration was tested in a lab environment with a Nile NSB (22.1.5) and ClearPass 6.9.4

### Prerequisites

It is assumed that a public/private digital server certificate, trusted by the dot1x clients, along with its CA has been uploaded to the ClearPass Policy Manager Certificate Store for RADIUS/EAP usage.
&#x20;It is also assumed that ClearPass has joined an Active Directory domain for the purpose of authentication and authorization against AD.

### Configuration

This document covers two components of 802.1x authentication:

A. Nile Portal, the authenticator (Nile NSB)
&#x20;B. The authentication server (ClearPass Policy Manager)

### A. Nile Portal

It is assumed that the Nile Portal ‘Service Areas’ and ‘DHCP’ are already configured. The following will illustrate the configuration of:

1. ClearPass as the radius server
2. The Nile Segments
3. The 802.1x SSID

### B. ClearPass Policy Manager

### 1. Import the Nile Dictionary

**XML Nile dictionary**

Using a text editor, copy the following Nile dictionary in XML format and paste it to a file. In this example, the file is called CPPM-Nile-Dictionary.xml



The file is also available from the support site at:

&#x20;**Import**

The Nile dictionary in XML format is imported into ClearPass Policy Manager as follows:

a. Go to **Administration > Dictionaries > RADIUS**

b. Click the ‘**Import**’ button to open the ‘Import from file’ window



![](https://nilesecure.com/wp-content/uploads/2024/02/6-1.png)


Once imported, the Nile dictionary attributes could be displayed by clicking the Nile dictionary:
&#x20;

![](https://nilesecure.com/wp-content/uploads/2024/02/5-2.png)

c. Select the Nile dictionary XML file, and click on the ‘**Import**’ button

Here is the content of an XML file. You can create an XML file with this content and import&#x20;

<BlockQuote>
  \<?xml version="1.0" encoding="UTF-8" standalone="yes"?>
  \<TipsContents xmlns=http\://www\.avendasys.com/tipsapiDefs/1.0>
  &#x20; \<TipsHeader exportTime="Thu Feb 20 11:15:40 CST 2025" version="6.10"/>

  &#x20;   \<Vendor vendorEnabled="false" prefix="Nile" name="Radius\:Nile" id="58313">

### 2. Add the Nile NSB as a Network Device

The NSB IP address communicating with ClearPass is typically of the format:
&#x20;aa.bb.cc.**6** if we assume the NSB subnet is aa.bb.cc.0/24.

In ClearPass Policy Manager:

a. Go to **Configuration > Network > Devices**

b. Click on ‘**Ad**d’ to open the ‘Add Device’ popup

c. Enter the following information, and click ‘**Add**’:

1. c.1 Name:
2. c.2 IP address
3. c.3 Radius secret



![](https://nilesecure.com/wp-content/uploads/2024/02/7-2.png)

### 3. Create the 802.1x wireless service

In this document, the 802.1x wireless service will leverage the Active Directory server for authentication and authorization of the Nile dot1x wireless clients.

- Navigate to **Configuration > Services:**
- Click on the ‘**Add**’ button, to add a new service.
- Select the Type as ‘**1X Wireless**’.
- Type a name for the new dot1x service. Example: Nile 802.1x wireless
- Fill up the new enforcement policy form:

![](https://nilesecure.com/wp-content/uploads/2024/02/11-2.png)


Click ‘**Next**’ twice to go to the ‘**Enforcement**‘ tab, and click on ‘**Add New Enforcement Policy**’:
&#x20;

![](https://nilesecure.com/wp-content/uploads/2024/02/10-1.png)


Click ‘**Next**’ to move to the ‘**Authorization**‘ tab and validate that the AD entry is present:
&#x20;

![](https://nilesecure.com/wp-content/uploads/2024/02/9-1.png)


Validate that the correct AD entry is present:
&#x20;

![](https://nilesecure.com/wp-content/uploads/2024/02/9-1.png)


Click ‘**Next**’ to move to the ‘**Authentication**’ tab to select the Authentication Methods and Sources:
&#x20;

![](https://nilesecure.com/wp-content/uploads/2024/02/8-1.png)

Add a third service rule to the existing two rules to leverage the Nile SSID sent as part of the ‘Called-Station-Id’ attribute, where the string could be either the full SSID name or a subset as illustrated below:
&#x20;

1. Type a ‘Name’: Nile 802.1x Enforcement Policy
2. Select a ‘Default Profile’: \[Deny Access Profile]
3. Keep the ‘Enforcement Type’ as: Radius
4. Click: ‘Add New Enforcement Profile’




Fill up the form to create a new enforcement profile:

![](https://nilesecure.com/wp-content/uploads/2024/02/12-2.png)

- Select the ‘Template’: Radius Based Enforcement
- Type a ‘Name’: Nile 802.1x Employee Profile
- Leave the ‘Action’ as: Accept
- Click ‘Next’

Fill up the Attributes form as follows:

![](https://nilesecure.com/wp-content/uploads/2024/02/13-2.png)

- Type: Radius\:Nile (the example shows Nilesecure dictionary)
- Name: netseg
- Value: type a string matching the desired Nile Portal Segment



![](https://nilesecure.com/wp-content/uploads/2024/02/15-2.png)


Click ‘Next’ to display the Summary, and then press ‘Save’ to save the first of two enforcement profiles needed in this document:
&#x20;

![](https://nilesecure.com/wp-content/uploads/2024/02/14-2.png)

Repeat steps i to k to create the second enforcement profile, where an illustration of the Summary is as shown below:



![](https://nilesecure.com/wp-content/uploads/2024/02/16-2.png)




Fill up the conditions by selecting the following, and press ‘Save’ when done:

![](https://nilesecure.com/wp-content/uploads/2024/02/17-2.png)

The next step is to add two rules to complete the ‘Nile 802.1x Enforcement Policy’ by pressing the ‘Add Rule’ button:
&#x20;

- Type: Authorization:
- Name: memberOf
- Operator: Contains
- Value: (‘Employee’ in this example)
- Profile Names: Nile 802.1x Employee Profile



![](https://nilesecure.com/wp-content/uploads/2024/02/18-2.png)




Press the ‘Next’ button to review the Summary of the new service ‘Nile 802.1x wireless’:

![](https://nilesecure.com/wp-content/uploads/2024/02/20-2.png)


Once back to the Services > Enforcement page, press the ‘Modify’ button to select the Enforcement policy completed in the previous step: ‘Nile 802.1x Enforcement Policy’:
&#x20;

![](https://nilesecure.com/wp-content/uploads/2024/02/19-2.png)

Repeat the previous step to add a second rule for ‘Contractors’. Once both rules are in place, press ‘Next’ to display the summary, and then press ‘Save’ to complete the creation of the “Nile 802.1x Enforcement Policy’:
&#x20;




Press the ‘Save’ button to complete the creation of the ‘Nile 802.1x wireless’ service.

![](https://nilesecure.com/wp-content/uploads/2024/02/21-2.png)

It is recommended to reorder this service and move it up the list of ClearPass services as needed.
